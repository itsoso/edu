# AI 推荐可信度 + 信息架构收敛产品设计

## 背景

当前产品已经具备完整的学习支持能力：错题、训练、任务、趋势、画像、作文、日记、费曼讲解、Guardian、Tutor、Curator、signals 和 student profile 都已经存在。

最近一次产品改造已经把首页推向“每日下一步”模式，但从实际页面结构看，产品仍然有两个全局问题：

- AI 推荐存在，但用户未必知道为什么该信任它
- 信息架构已经分主次，但页面和侧栏仍暴露大量功能入口

下一轮改进不应继续堆新模块，而应把现有能力收敛成一条可信主线：

`打开今日 -> 系统给一个推荐动作 -> 解释为什么 -> 完成后反馈 -> 成长页证明长期有效`

## 目标

把产品从“有很多 AI/学习模块”收敛成“可信的每日学习操作系统”。

核心目标：

- 学生每天打开后只需要面对一个主要动作
- 推荐动作必须解释清楚“为什么是这个”
- 用户可以反馈推荐是否合适
- 成长页能证明推荐是否真的让学习变稳
- 一级导航从功能仓库收敛为 5 个稳定入口

## 非目标

- 不引入复杂机器学习模型
- 不重写所有页面
- 不改变现有多租户、session、Bearer token 认证结构
- 不把日记、反思、作文正文送入 LLM 或 signals
- 不把 Guardian、Tutor、Curator 全部合并成一个大 agent

## 推荐方案

采用“先收敛信息架构，再增强推荐解释”的渐进方案。

原因：

- `next-action`、signals、profile、Guardian、Tutor、Curator 的地基已经存在
- 当前最大问题不是“不会推荐”，而是“推荐没有成为唯一可信主线”
- 页面收敛和推荐解释能最快提升用户感知
- 规则推荐更容易测试、解释和调优

## 信息架构

主导航只保留 5 个入口：

| 主入口 | 角色 | 包含模块 |
| --- | --- | --- |
| 今日 | 唯一行动入口 | next-action、今日反馈、必要提醒、今日任务 |
| 错题 | 漏洞收集与整理 | 扫试卷、错题本、错题详情 |
| 训练 | 漏洞修补 | 训练集、继续训练、打印练习 |
| 成长 | 长期证明 | 趋势、画像、月报、方法卡 |
| 我的 | 个人表达与设置 | 日记、作文、费曼、设置 |

桌面侧栏不再直接列出所有二级功能。二级功能只在对应聚合页出现。

这样做的产品效果：

- 入口从“我该点哪个”变成“我今天先做什么”
- 高频行动和低频查看分离
- AI 推荐可以成为产品主线，而不是众多模块中的一个卡片

## 今日页设计

今日页改成三段。

### 1. 唯一主动作卡

顶部只放一个主动作卡。

固定信息结构：

- 今天先做这个
- 动作标题
- 推荐原因
- 证据
- 预计耗时
- 主按钮
- 反馈入口

示例：

```text
今天先做这个
先补 2 道分式方程训练

为什么是它：
这类题最近重复错了 3 次，上一组训练只做对 1/3。

预计 12 分钟
[立即开始]

不合适？太难了 / 已经会了 / 今天不想做
```

### 2. 完成反馈

主动作完成后，今日页显示轻反馈。

推荐反馈语义：

- 今天补掉了一个反复出现的漏洞
- 这组训练已经完成
- 这个知识点正在变稳
- 明天会根据今天结果调整推荐

避免反馈语义：

- 积分
- 排行榜
- 大量徽章
- 夸张鼓励

### 3. 折叠的次要信息

以下内容不再抢主视觉：

- GuardianAlerts
- WeekendCoursesCard
- TutorCard
- CuratorBlock
- CoachWeekCard
- WeeklyGoalCeremony
- 今日任务完整列表
- AI daily tip
- 快捷入口

它们可以放在“今天其他事项”或完成主动作后的区域里。

## 推荐可信度设计

`next-action` 从“给一个动作”升级为“给一个可解释动作”。

建议返回结构：

```ts
type NextAction = {
  kind: 'mistake' | 'practice' | 'task'
  title: string
  description: string
  cta_label: string
  cta_path: string
  subject?: string | null
  knowledge_point?: string | null
  source_mistake_id?: number | null
  practice_set_id?: number | null
  task_id?: number | null
  estimated_minutes?: number | null
  reason: {
    primary: string
    evidence: string[]
    confidence: 'high' | 'medium' | 'low'
  }
  alternatives?: NextActionAlternative[]
}
```

第一版 `reason` 由规则生成，不需要 LLM。

示例：

```json
{
  "primary": "这类题最近重复出错",
  "evidence": [
    "知识点：分式方程",
    "未掌握错题：3 道",
    "最近一组训练正确率：1/3"
  ],
  "confidence": "high"
}
```

## 用户反馈

推荐卡提供轻量反馈：

- 就做这个
- 今天不想做
- 太难了
- 已经会了

反馈写入 `interaction_signals`。

建议新增事件：

- `next_action.feedback`

payload 白名单：

- `kind`
- `feedback`
- `cta_path`
- `reason_primary`

反馈用途：

- `太难了`：下次降低难度或推荐更短动作
- `已经会了`：降低该错题/训练优先级，必要时引导标记掌握
- `今天不想做`：当天不重复推荐同类动作
- `就做这个`：作为推荐命中信号

## 推荐排序规则

第一版保持规则排序，确保可解释和可测试。

### 错题排序

优先级因子：

- 同知识点未掌握错题数量
- 最近新增
- 尚未生成训练
- 长时间未处理
- 与本周目标相关

推荐文案：

- “这类题最近重复出错”
- “这道题刚加入，还没处理”
- “它还没有对应训练”

### 训练排序

优先级因子：

- 正确率低
- 尚未完成
- 最近做错
- 与本周目标相关
- 上次被用户反馈“太难了”后应降难度

推荐文案：

- “这组训练还没完全稳住”
- “上一组正确率偏低”
- “还有题没完成”

### 任务排序

优先级因子：

- 今天到期
- 连续未完成
- 家长布置
- 预计耗时短

推荐文案：

- “今天还有一个短任务”
- “这个任务已经拖了几天”
- “这是家长布置的任务”

### 异常信号调整

如果 Guardian 或 signals 表明用户最近有放弃、疲劳或节奏过高信号，推荐应变轻：

- 预计耗时更短
- 题目数量更少
- 避免连续推荐高难训练
- 文案从“补漏洞”改为“先做一个小动作”

## 成长页重组

成长页不再只是入口集合，而是回答：

“系统推荐的事情有没有真的让你变稳？”

建议结构：

### 1. 本周推荐命中

展示：

- 本周推荐次数
- 点击次数
- 完成次数
- 用户反馈分布

### 2. 漏洞变化

展示：

- 反复错的知识点
- 最近是否有训练
- 正确率是否改善
- 是否从“反复错”变为“在变稳”

### 3. 推荐解释回放

展示最近 5 次推荐：

- 推荐了什么
- 为什么推荐
- 用户是否完成
- 后续结果如何

### 4. 二级入口

以下作为成长页内的二级入口：

- 成绩趋势
- 看见自己
- 月度复盘
- 方法卡

## 家长视角

家长端也受益于同一套推荐解释。

家长不需要看到完整功能导航，而是看：

- 今天推荐孩子做什么
- 为什么推荐
- 孩子有没有处理
- 最近推荐是否真的让某个漏洞变稳
- 今晚应该怎么聊

家长端文案应避免监控感，强调陪伴和理解。

## 数据与隐私

保持现有隐私边界：

- signals 只存元数据
- 日记、反思、作文正文不进 signals
- profile 构建只使用允许的统计和摘要
- `next-action` 解释使用结构化数据，不需要 LLM 读取私密正文

## 成功指标

核心指标：

- 今日主动作点击率
- 推荐动作完成率
- `next_action.feedback` 分布
- 从推荐进入训练后的完成率
- 推荐动作完成后的次日回访率
- 成长页推荐回放查看率

辅助指标：

- 一级导航点击分布是否更集中
- 更多功能入口点击是否下降但关键动作完成率上升
- 家长端停留是否集中在风险、进展、沟通建议区域

## 分阶段路线

### P0

- 扩展 `NextAction` 返回解释字段
- 首页主动作卡展示推荐原因、证据、预计耗时
- 新增推荐反馈 signals
- 收敛桌面侧栏，只展示 5 个主入口
- 二级功能迁移到聚合页

### P1

- 成长页新增“推荐是否有效”视图
- 推荐排序纳入用户反馈
- 训练完成后展示下一步反馈
- 家长端复用推荐解释

### P2

- 将 Guardian 异常信号纳入推荐难度调节
- 将 student profile 中的知识点趋势纳入排序
- 增加推荐回放与长期成长叙事

## 风险

### 风险 1：过度收敛导致功能难找

缓解：

- 保留聚合页二级入口
- 搜索或“更多”仅作为低频工具
- README 和页面文案同步入口变化

### 风险 2：推荐解释显得机械

缓解：

- 第一版先用短规则文案
- 只展示 2-3 条证据
- 避免长篇分析

### 风险 3：用户反馈后排序无变化

缓解：

- 第一版至少做到当天不重复推荐被拒绝类型
- P1 再做长期权重调整

## 结论

下一轮产品改进应优先把推荐变成可信主线，而不是继续增加 AI 能力。

关键不是让系统显得更聪明，而是让学生每天打开时相信：

“它知道我现在最该做什么，而且说得清为什么。”
